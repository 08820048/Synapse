# Synapse 产品需求文档

**版本**：v3.0  
**日期**：2026 年 8 月  
**技术栈**：Rust + GPUI  
**定位**：高性能、本地优先的原生 Markdown 编辑器

## 1. 产品概述

Synapse 面向需要长期编辑本地 Markdown 文件的用户，提供启动迅速、内存占用低、文件操作可靠的原生桌面体验。软件直接打开普通文件夹，不绑定专有数据库或云服务，用户可随时使用其他工具访问同一批文件。

当前路线聚焦 Markdown 文件管理、多文档编辑、专业输入体验、快速命令与搜索。

## 2. 核心目标

1. 提供稳定可靠的本地 Markdown 打开、编辑和保存闭环。
2. 在大量文件和长文档场景保持快速启动与流畅交互。
3. 提供接近 Zed 的紧凑、连续、键盘优先原生界面。
4. 使用普通目录和 `.md` 文件，避免数据锁定。
5. 保证未保存内容不会因页签、目录或窗口操作被静默丢弃。

## 3. 目标用户

- 使用 Markdown 写作、记录项目或维护技术文档的程序员和创作者。
- 重视本地存储、隐私和跨工具兼容性的用户。
- 对 Electron 编辑器启动速度、内存和大文件表现不满意的用户。
- 需要同时打开多个 Markdown 文件并快速切换的人。

## 4. 功能规划

### 4.1 当前基础能力

- 打开本地文件夹并递归发现 Markdown 文件。
- 分层目录与文件导航。
- 多文档页签与独立编辑状态。
- Rope 文本缓冲区和基础 Unicode 编辑。
- 原子保存、错误反馈和未保存内容保护。
- 页签右键关闭操作。
- 可收起左侧导航与中央编辑器。
- 搜索启动器和中央命令面板外壳。
- 包含空目录的递归文件树；目录支持展开/收起，展开态使用 `folder-open`，展开的空目录显示“空文件夹”。
- 根目录/任意子目录可立即创建同级顺序编号的 `未命名N` 文件夹或笔记，无需预先命名。
- 新建笔记自动打开并以 `# 未命名N` 初始化；本次新建会话内编辑一级标题会同步重命名 Markdown 文件。
- 文件夹和笔记右键菜单：新建、重命名、Finder 定位和系统废纸篓。
- 文件夹和笔记采用文件树原位重命名输入，支持中文 IME、Enter 提交和 Escape 取消。
- 文件夹/笔记拖拽移动、覆盖冲突保护和文件夹递归移动保护。
- 页签右键菜单按鼠标位置显示并限制在窗口内；左侧栏开关常驻编辑器底栏，底栏与 Settings 行等高。
- 目录、搜索面板、页签、侧栏和右键菜单统一遵守 `过渡和交互动画规约.md`。
- 文件操作后的即时快照刷新，以及干净页签路径迁移和脏页签操作保护。

### 4.2 近期编辑器能力

- 鼠标光标定位、文本选择、IME、剪贴板、撤销和重做。
- Markdown 语法高亮、常用编辑快捷键和大纲。
- 文件监听与外部变更冲突处理。
- 自动保存和崩溃恢复。
- 页签拖拽排序与会话恢复。

### 4.3 导航与效率能力

- 文件名和内容搜索。
- 模糊匹配、结果高亮和键盘导航。
- 命令面板统一承载新建、打开、设置和编辑器命令。
- Todo 与 Bookmark 快捷入口及本地持久化。
- 最近打开文件与目录。
- 可配置快捷键、主题和字体。

### 4.4 后续增强

- Markdown 实时预览与分屏预览。
- 图片拖入、资源目录管理和链接补全。
- 代码块语法高亮与数学公式。
- PDF、HTML 和纯文本导出。
- 多窗口和拆分编辑器。
- 可选插件接口。

## 5. 界面与交互

默认布局由左侧导航与中央编辑区构成：

```text
┌──────────────────────────────────────────────────────┐
│ 顶部工具栏：侧栏开关 / 目录 / 状态 / 打开目录       │
├───────────────┬──────────────────────────────────────┤
│ 搜索入口      │ 文档页签                             │
│ Todo          ├──────────────────────────────────────┤
│ Bookmarks     │                                      │
│ ───────────   │ Markdown 编辑器                      │
│ Notes   +  +  │                                      │
│ 文件夹/文件树 │                                      │
│               ├──────────────────────────────────────┤
│ Settings      │ 状态栏                               │
└───────────────┴──────────────────────────────────────┘
```

交互原则：

- 编辑器是视觉与交互中心。
- 面板使用连续背景和细分隔线，不使用割裂的浮动卡片。
- 搜索入口点击后在窗口中央打开命令面板，不在侧栏直接输入。
- 常用操作优先支持键盘，也必须保留清晰的鼠标入口。
- 所有图标与工具栏控件保持统一尺寸和垂直中心线。
- 长文件名和长文本不得撑破窗口布局。

## 6. 非功能要求

| 类别 | 目标 |
|---|---|
| 冷启动 | 参考 Apple Silicon 开发机目标低于 0.8 秒 |
| 空闲内存 | 目标低于 80 MB |
| 长文件 | 1 万行以上仍可流畅滚动和编辑 |
| 大目录 | 数千 Markdown 文件下导航和搜索保持响应 |
| 数据安全 | 本地文件为真实数据源；保存失败不清除脏状态 |
| 网络 | 核心编辑流程不发起网络请求 |
| 跨平台 | macOS、Windows、Linux 保持一致核心行为 |
| 可访问性 | 核心命令逐步实现完整键盘导航和可见焦点 |

## 7. 技术架构

- `synapse-core`：Vault、路径验证、递归目录快照、文件操作、系统废纸篓、Markdown 文档、Rope 缓冲区和原子保存。
- `synapse-ui`：GPUI 窗口、导航、文件菜单与拖拽、页签、命令面板和编辑器视图。
- 后续 `editor`：输入法、选择、撤销栈、语法高亮和渲染。
- 后续 `search`：文件名与内容索引。
- 后续 `config`：设置、主题、快捷键和会话恢复。

禁止在核心桌面应用中引入 Web UI 技术或强制在线服务。

## 8. 数据模型

### Vault

- 本地 Markdown 目录的规范化绝对路径。
- 文件发现快照包含真实目录和 Markdown 笔记，均从文件系统重新生成。

### MarkdownDocument

- Vault 相对路径。
- Rope 文本缓冲区。
- 当前修订号和已保存修订号。

### EditorTab

- 一个打开的 `MarkdownDocument`。
- 独立 Unicode 字符光标。
- 活动状态和脏状态。

### EditorSession

- 当前 Vault。
- 打开的页签集合。
- 活动页签。
- 导航、命令面板和窗口布局状态。

## 10. 当前明确不做

- 强制账户、云同步或网络服务。
- Electron 或其他 Web 容器。

## 11. 成功标准

- 用户可以从应用内打开目录，连续完成文件选择、页签切换、编辑和保存。
- 未保存内容在页签和目录操作中得到可靠保护。
- 界面被感知为紧凑、原生、连贯，而非多个割裂面板。
- 启动、内存和长文档表现明显优于常见 Web 技术编辑器。
