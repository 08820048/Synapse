# Spec: 通知系统与危险操作确认

**Author:** Codex
**Date:** 2026-08-14
**Status:** Approved
**Reviewers:** 用户（以《通知系统规范》《危险操作确认效果规范》作为已批准需求来源）
**Related specs:** `docs/通知系统规范.md`、`docs/危险操作确认效果规范.md`

## Context

Synapse 目前会直接执行删除待办、删除书签、删除标签、移除标签关联、清除已完成待办以及将笔记或文件夹移到废纸篓等操作。用户没有统一的二次确认，也无法从界面获知操作最终成功还是失败；切换工作区成功后同样没有明确反馈。

本功能为这些高风险操作增加统一的 GPUI 原生确认流程，并建立可复用的右上角通知入口。实现必须沿用 Rust + GPUI 架构，不引入 Web 技术，并同时支持简体中文和英文。

## Functional Requirements

- FR-1: 系统 MUST 使用 `gpui-component` 的 `Alert` 状态变体呈现信息、成功、警告和错误通知。
- FR-2: 通知 MUST 显示在当前软件窗口右上角、允许用户关闭，并在 5 秒后自动消失。
- FR-3: 系统 MUST 在危险操作成功后显示成功通知，在执行失败后显示错误通知。
- FR-4: 系统 MUST 在工作区切换成功后显示成功通知，在切换失败后显示错误通知。
- FR-5: 用户直接发起删除、移到废纸篓、批量清除或移除关联时，系统 MUST 在修改数据前显示 `AlertDialog` 的 “Delete File” 风格确认界面。
- FR-6: 危险操作确认框 MUST 提供取消按钮和危险样式的确认按钮；取消 MUST NOT 修改数据。
- FR-7: 确认按钮 MUST 只执行一次对应操作，完成后 MUST 关闭确认框并显示结果通知。
- FR-8: 确认框和通知的标题、说明与按钮文案 MUST 根据应用当前语言显示简体中文或英文。
- FR-9: 待办自动清理是用户预先启用的自动策略，系统 MUST NOT 为每条自动清理再次弹出确认框或通知，以免阻断连续操作。
- FR-10: 系统 SHOULD 以单一复用入口定义危险操作的确认标题、说明、按钮文案和执行逻辑，避免各功能产生不一致行为。
- FR-11: 系统 MUST 使用现有 `Root` 通知与对话框层，不得引入新的窗口、浏览器或网络依赖。

## Non-Functional Requirements

- NFR-P1: 打开确认框的同步处理 SHOULD 在 16 毫秒内完成，不得执行磁盘扫描或网络请求。
- NFR-P2: 通知队列 MUST 将单次可见通知数量限制为组件既有上限 10 条，避免无界渲染增长。
- NFR-R1: 取消确认、按 Escape 或关闭确认流程 MUST 保持数据和持久化文件不变。
- NFR-R2: 当持久化失败时，内存状态 MUST 与失败前一致，或由现有领域操作的回滚机制恢复。
- NFR-A1: 确认框 MUST 支持 Escape 取消和 Enter 确认。
- NFR-A2: 危险确认按钮 MUST 使用设计系统的 Danger 变体，不能只依赖文字表达风险。
- NFR-I1: 新增用户可见文本 MUST 同时具有简体中文和英文版本。

## Acceptance Criteria

### AC-1: 删除前确认 (FR-5, FR-6, NFR-A2)
Given 用户在文件、文件夹、笔记、待办、书签或标签上触发删除类操作
When 危险操作被请求
Then 数据保持不变并显示带取消按钮和危险确认按钮的确认框
And 确认框说明中显示操作对象名称或数量

### AC-2: 取消不修改数据 (FR-6, NFR-R1)
Given 危险操作确认框已经打开
When 用户点击取消或按 Escape
Then 确认框关闭
And 对应对象仍然存在且不显示成功通知

### AC-3: 确认后成功通知 (FR-2, FR-3, FR-7)
Given 危险操作确认框已经打开且底层操作能够成功
When 用户点击危险确认按钮或按 Enter
Then 对应操作恰好执行一次
And 确认框关闭
And 窗口右上角显示可关闭的成功通知并在 5 秒后自动消失

### AC-4: 执行失败通知 (FR-3, NFR-R2)
Given 危险操作确认框已经打开且底层操作返回错误
When 用户确认操作
Then 确认框关闭
And 窗口右上角显示可关闭的错误通知
And 应用继续运行且内存状态不保留失败修改

### AC-5: 工作区切换反馈 (FR-4)
Given 用户选择了一个工作区目录
When 工作区加载成功或失败
Then 窗口右上角分别显示成功或错误通知

### AC-6: 双语文案 (FR-8, NFR-I1)
Given 应用语言分别设置为简体中文或英文
When 显示通知或危险操作确认框
Then 标题、说明、确认和取消文案全部使用对应语言

### AC-7: 自动清理不阻断 (FR-9)
Given 用户已开启完成待办自动清理
When 用户将一条待办标记为完成并等待自动清理
Then 待办按既有延迟动画自动移除
And 不显示危险操作确认框或逐条清理通知

### AC-8: 使用设计系统组件 (FR-1, FR-5, FR-11)
Given 应用渲染通知或危险确认
When 检查创建的 UI 元素
Then 通知内容由 `Alert` 的对应状态构建
And 确认流程由 `gpui-component` 的对话框层和 Danger 按钮变体构建

### AC-9: 统一危险操作入口 (FR-10)
Given 任一待办、书签或文件树危险操作被触发
When 代码请求二次确认
Then 操作通过同一个 `DangerousAction` 入口生成双语文案并执行
And 功能模块不直接调用底层删除或移除方法

## Edge Cases

- EC-1: 对象在确认框打开后已被外部文件监听或其他操作移除时，确认执行 MUST 返回错误通知且不得崩溃。
- EC-2: 连续触发多个通知时，通知 MUST 由组件队列管理并各自可关闭、自动消失。
- EC-3: 清除已完成待办的计数为 0 时，系统 MUST NOT 打开确认框。
- EC-4: 删除标签会解除多个对象关联时，确认说明 MUST 明确该标签将被删除，而不是描述为仅从当前对象移除。
- EC-5: 移除标签关联 MUST 只解除关联，不得删除标签本身。
- EC-6: 工作区选择器被用户取消时，系统 MUST NOT 显示成功或错误通知。

## API Contracts

本功能不新增网络 API。应用内接口契约如下：

```rust
fn push_alert_notification(
    window: &mut Window,
    cx: &mut App,
    variant: AppNotificationVariant,
    title: impl Into<SharedString>,
    message: impl Into<SharedString>,
);

fn request_dangerous_action(
    action: DangerousAction,
    app: Entity<SynapseApp>,
    window: &mut Window,
    cx: &mut App,
);
```

- `push_alert_notification` MUST 使用 `WindowExt::push_notification`，并以 `Notification::content` 承载实际 `Alert` 变体。
- `request_dangerous_action` MUST 通过 `WindowExt::open_dialog` 创建不可点击遮罩关闭、可键盘取消/确认的确认框。
- 领域操作 MUST 返回 `Result` 或等价成功状态，以便确认回调选择成功或错误通知。

## Data Models

```rust
enum AppNotificationVariant {
    Info,
    Success,
    Warning,
    Error,
}

enum DangerousAction {
    TrashTreeEntry { relative_path: PathBuf, display_name: String },
    TrashActiveNote { relative_path: PathBuf, display_name: String },
    DeleteTodo { id: u64, display_name: String },
    ClearCompletedTodos { count: usize },
    DeleteTodoTag { id: u64, display_name: String },
    RemoveTodoTagAssignment { todo_id: u64, tag_id: u64, display_name: String },
    DeleteBookmark { id: u64, display_name: String },
    DeleteBookmarkTag { id: u64, display_name: String },
    RemoveBookmarkTagAssignment { bookmark_id: u64, tag_id: u64, display_name: String },
}
```

这些模型只存在于运行时，不新增持久化格式，也不改变现有工作区、待办和书签数据文件结构。

| Field | Type | Constraints |
|---|---|---|
| `AppNotificationVariant` | enum | 仅允许 `Info`、`Success`、`Warning`、`Error` |
| `DangerousAction` | enum | 每个变体必须包含执行所需标识及面向用户的对象名称或数量 |
| `DangerousActionCopy.title` | `String` | 必须与当前应用语言一致且非空 |
| `DangerousActionCopy.description` | `String` | 必须说明具体对象或批量数量 |
| `DangerousActionCopy.confirm_label` | `String` | 必须与当前应用语言一致且对应 Danger 按钮 |

## Out of Scope

- OS-1: 软件更新检查和安装流程当前不存在，因此本次不实现 “Install Update” 确认框；未来更新功能 MUST 复用同一对话框系统。
- OS-2: 本次不新增撤销功能；未来新增会破坏持久化状态的撤销操作时 MUST 接入危险确认。
- OS-3: 不为每次自动保存、光标移动等高频或无明确结果的编辑行为显示通知。
- OS-4: 不改变待办自动清理的既有延迟和平移动画。
