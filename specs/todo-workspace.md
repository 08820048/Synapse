# 原生待办工作区与标签管理规格

## 目标

在现有 Rust + GPUI 桌面架构内，将侧边栏“待办”主区域连接到独立工作区，并完成标签列表、待办创建、筛选、完成状态和本地持久化。该工作区占用原编辑器内容区域，不引入 WebView、HTML、CSS 或 JavaScript。

## 功能要求

- FR-1：侧边栏待办行必须拆分为两个互不重叠的入口；点击加号左侧主区域进入待办工作区，点击右侧加号不得触发该视图切换。
- FR-2：进入待办工作区后，当前笔记页签不再显示激活状态；点击任意笔记页签、文件树笔记或新建笔记会返回笔记编辑视图。
- FR-3：待办工具栏左侧面包屑位置固定显示“待办”，右侧显示带 Lucide `tag` 图标的“新建标签”操作。
- FR-4：点击“新建标签”后，原操作位置切换为 GPUI 原生单行输入框；输入框右侧必须内嵌勾选和关闭两个独立按钮。
- FR-5：点击勾选按钮会去除名称首尾空白并创建标签；空名称、超过 48 个字符或不区分大小写的同名标签必须拒绝，并显示中文错误信息。
- FR-6：点击关闭按钮会清空输入、关闭输入框并恢复“新建标签”按钮，不创建标签。
- FR-7：新建成功的标签必须立即显示在左侧标签栏并成为当前选中项；标签栏顶部显示“全部”，每行右侧显示稳定宽度的使用计数。
- FR-8：“添加待办…”必须是支持中文 IME 的 GPUI 原生单行输入框，左侧固定显示 20px Lucide `plus` 图标；进入待办工作区时输入框自动获得焦点。
- FR-9：输入内容按回车后去除首尾空白并创建待办；空内容和超过 500 个字符的内容必须拒绝并显示中文错误，创建成功后清空输入且保持焦点。
- FR-10：待办主体使用编辑器主题背景、900px 最大内容宽度、168px 标签栏与右侧弹性内容区；窄窗口继续保持双栏可用，不允许横向溢出。
- FR-11：所有标签筛选行、确认/取消和侧边栏入口保持至少 40px 命中尺寸，点击区域不得重叠。
- FR-12：新待办插入列表顶部；当前筛选为具体标签时自动关联该标签，筛选为“全部”时不关联标签。
- FR-13：“全部”计数使用实际待办总数，各标签计数使用实际关联数；切换标签只显示属于该标签的待办。
- FR-14：每条待办提供不小于 40px 的复选框命中区域；切换完成状态后即时更新为勾选、弱化文字和删除线样式。
- FR-15：标签名称写入平台用户配置目录的 `Synapse/todo-tags`，待办文本、完成状态、稳定 ID 和多标签关系写入同目录的 `Synapse/todo-items`；应用重启后按原顺序恢复。
- FR-16：待办持久化字段必须转义反斜杠、制表符和换行，损坏记录不得导致应用崩溃或阻止其他有效记录加载。
- FR-17：添加待办输入行的 Lucide `plus` 必须直接设置主题弱化色，不允许依赖父容器的 `currentColor` 继承；浅色和深色主题均需可见。
- FR-18：具体待办行之间不得绘制顶部分割线或底部分割线；整行在普通、悬停和标签面板打开状态下都必须保持编辑器原背景，不得显示灰色矩形、圆角卡片、边框或其他行级表面反馈，悬停只允许改变右侧三个操作图标的可见性。
- FR-19：鼠标进入待办行或其任意子控件时，最右侧必须通过 GPUI 原生 `group/group_hover` 显示“分配标签、复制、删除”三个 Lucide 图标操作，不得依赖应用状态回写后再重绘；每个操作保留独立 40×40px 命中区，离开后隐藏，标签面板打开期间继续显示。
- FR-20：点击“分配标签”后，在图标下方显示窗口级右对齐浮层；浮层列出全部已注册标签、标签色圆点和当前勾选状态，点击项目即时切换且保持面板打开，从而支持连续多选。
- FR-21：已分配标签必须显示在待办文本下方，格式为 `#标签名` 的彩色胶囊；每个胶囊右侧提供 X，点击只取消该标签与当前待办的关联。
- FR-22：点击复制必须把当前待办纯文本直接写入系统剪贴板；点击删除必须从内存列表和 `Synapse/todo-items` 中完全移除该待办，并同步更新筛选结果和计数。
- FR-23：多标签持久化升级必须继续读取旧版单标签记录；新格式使用带版本前缀的长度编码，不能把中文、分隔符或转义字符拆坏。
- FR-24：右侧引导文案同行最右侧必须在存在完成项时显示“清除已完成 · N”文本按钮，N 为全部已完成待办的实时数量；点击后一次删除全部完成项、关闭属于已删除待办的标签浮层并立即持久化，未完成项不得受影响；N 为 0 时隐藏按钮。

## 验收标准

- AC-1：点击“待办”文字区域进入待办视图，点击同一行右侧加号只执行其独立回调。
- AC-2：工具栏显示“待办”和“新建标签”；点击后切换为可输入中文的原生输入框，勾选和 X 均位于输入框内部右侧。
- AC-3：添加“工作”后左栏立即出现彩色圆点、“工作”和计数 0；重输“工作”或“工作”的大小写变体不会重复创建。
- AC-4：点击 X 后输入框关闭且列表不变。
- AC-5：保存再加载标签配置后名称和顺序保持一致，选中状态恢复为“全部”。
- AC-6：项目不新增 Web 技术、浏览器运行时或前端依赖；标签图标来自项目固定的 Lucide 1.27.0 资源。
- AC-7：点击“待办”后可直接输入中文内容；按回车后输入框清空、新待办出现在列表首位，空白输入不会创建记录。
- AC-8：选中“工作”后创建待办，左侧“全部”和“工作”计数均增加 1；切换“全部”与“工作”时列表筛选结果正确。
- AC-9：点击待办复选框后立即显示完成样式；退出并重新启动应用后，文本、标签关系、顺序和完成状态保持不变。
- AC-10：待办输入行保持单一透明表面，左侧大号加号与文本输入区垂直居中，不额外嵌套边框或装饰卡片。
- AC-11：浅色和深色模式下，“添加待办…”左侧均显示 20px 加号；待办列表项之间没有横向分割线。
- AC-12：鼠标进入任意待办行后，最右侧出现标签、复制和 X 三个图标；移到另一行时操作区域跟随目标行，不能占据或挤动文本布局。
- AC-13：打开标签浮层并依次勾选“工作”“紧急”后，两项保持同时勾选，待办下方出现 `#工作` 与 `#紧急` 两个胶囊，左栏两个标签计数均包含该待办。
- AC-14：点击 `#紧急` 胶囊右侧 X 后只移除“紧急”；点击复制后系统剪贴板等于待办文本；点击删除后该待办立即消失且重启后不恢复。
- AC-15：存在旧版单标签 `todo-items` 时升级后仍可加载、筛选和重新保存，不要求用户手动迁移数据。
- AC-16：完成 2 条待办后，右侧引导行显示“清除已完成 · 2”；点击后两条完成项同时消失，未完成项、标签筛选和计数保持正确，按钮随完成数归零而隐藏，重启后已清除项目不恢复。

## 本阶段之外

- 编辑待办文本。
- 标签重命名、删除、拖拽排序与自定义颜色。
- 标签与 Markdown 任务列表之间的同步。
