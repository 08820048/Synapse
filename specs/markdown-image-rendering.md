# Markdown 图片渲染规格

## 语法与显示

- 支持标准 Markdown 独立图片 `![alt](path)` 和混排的行内图片。
- 图片标题不参与路径解析；尖括号目标、反斜杠转义和百分号编码路径可正常识别。
- 独立图片按固有尺寸居中显示，不主动放大小图，最大宽度受正文区域限制，最大高度为 720px。
- 行内图片按 22px 高度参与文本流，最大宽度 180px；加载失败时在原位置显示 `alt` 文本。
- 默认编辑态下图片持续渲染；光标进入或点击图片不得自动恢复源码，完整图片语法通过右上角 Markdown 源码模式查看和编辑。

## 图片来源

- 相对路径以当前笔记所在目录为基准，例如 `../assets/image.png`。
- `/assets/image.png` 形式以当前 Vault 根目录为基准，不解释为操作系统绝对路径。
- HTTP(S) 图片由应用启动时注入的真实 Rust HTTP 客户端和 GPUI 原生异步资源加载器读取；Reqwest/Hyper 的连接、TLS、重定向和响应读取必须运行在客户端自有 Tokio runtime 内，禁止直接由 GPUI 非 Tokio executor 轮询。支持系统根证书、HTTPS、最多 10 次重定向与 30 秒超时；PNG、JPEG、WebP、GIF、SVG、BMP、TIFF 等格式由 GPUI 解码。
- 本地路径进行百分号解码、词法规范化和 canonicalize 校验；禁止 `..` 或符号链接越过当前 Vault。
- 拒绝 `file:`、`data:` 和其他非 HTTP(S) URI scheme，并用明确错误占位保留 `alt` 与失败原因。

## 缓存与错误

- 图片解析结果按 Vault、笔记路径和文档 revision 缓存，普通光标移动复用路径解析结果。
- 实际图片字节和动画帧复用 GPUI 全局图片缓存，避免滚动或重绘时重复解码。
- 文件不存在、目录目标、非法百分号编码、越界路径和加载/解码失败均不导致编辑器崩溃。

## 剪贴板图片

- `Cmd/Ctrl+V` 优先识别 GPUI 剪贴板中的图片条目；没有图片时继续执行既有文本粘贴。
- 图片保持剪贴板声明的 PNG、JPEG、WebP、GIF、SVG、BMP 或 TIFF 原始字节与扩展名，不做有损转码。
- 图片保存到当前笔记所在目录的 `assets/` 子目录，并插入 `![Pasted image](assets/文件名.ext)`；目录不存在时自动创建。
- 文件名采用毫秒时间戳，发生碰撞时追加递增序号；文件以 `create_new` 方式创建，不覆盖任何已有附件。
- 没有活动笔记、图片为空或文件系统写入失败时不修改文档，并记录明确错误。

## 验收

- `docs/assets/markdown-image-test.svg` 提供可复现的本地图片测试资源，完整性测试文档同时覆盖本地、远程、缺失和带链接图片语法。
- 自动化测试覆盖独立/行内结构、活动行源码恢复、编码中文路径、笔记相对路径、Vault 根路径、远程 URL、越界拒绝、缓存键、真实 HTTP 客户端初始化、从非 Tokio executor 发起真实本地 HTTP 请求，以及剪贴板附件落盘与文件名碰撞。
- 只执行格式化、严格 Clippy、workspace 测试、开发构建和差异检查；不启动应用、不执行截图或自动 UI 操作。
