# 原生书签工作区与侧栏集合规格

## 目标

在现有 Rust + GPUI 架构中实现完整书签管理，不引入 WebView、HTML/CSS 或 JavaScript。交互参考 Ornata 的书签工作区和侧栏集合，但数据、网络请求、渲染与持久化均由 Synapse 原生实现。

## 功能要求

- FR-1：侧栏“书签”行必须拆分为两个互不串行的区域；左侧图标和文字只打开书签工作区，右侧 Lucide `plus` / `minus` 只展开或收起完整书签列表。
- FR-2：完整工作区占用编辑器区域，工具栏左侧显示“书签”，右侧提供“导出”和“新建标签”。
- FR-3：正文使用居中的 940px 最大宽度，左侧为 168px 标签栏，右侧为搜索、添加链接和书签列表。
- FR-4：标签栏显示“全部”、标签色圆点与真实使用计数；选择标签后列表只显示已分配该标签的书签。
- FR-5：新建标签必须支持中文 IME、Enter/勾选提交和 X 取消；空名称、重名和超过 48 字符必须阻止。
- FR-6：标签可删除；删除标签时同步清除所有书签的该标签关系，不删除书签。
- FR-7：搜索框同时承担搜索和添加：普通文本按标题、URL、标签过滤；有效裸域名或 HTTP(S) URL 按 Enter 保存，裸域名自动补 `https://`。
- FR-8：重复 URL、空输入、非 HTTP(S) URL 不得创建；新书签置顶，并继承当前选中的标签。
- FR-9：保存后通过应用已有的 Rust HTTP 客户端异步获取 Open Graph 标题/图片、网页标题和 favicon；失败不得崩溃、阻止使用或形成无限重试。
- FR-10：书签行显示 56×40 预览图；没有预览时降级 favicon，再降级到 Lucide `globe`。
- FR-11：点击书签行使用系统浏览器打开 URL；双击标题原位编辑，支持中文；悬停显示分配标签、复制链接和删除三个操作。
- FR-12：标签分配浮层支持多选；已分配标签显示为 `#标签` 胶囊，X 只移除当前关系。
- FR-13：导出使用系统保存面板，输出包含标题、URL 和标签的 Markdown 列表。
- FR-14：标签注册表、书签稳定 ID、URL、标题、预览、favicon、抓取状态、多标签关系和创建时间必须持久化到平台用户配置目录；损坏记录跳过，不能使应用启动失败。
- FR-15：侧栏展开列表显示全部书签、第一标签的颜色圆点和省略号标题；点击条目直接打开 URL，不切换工作区。
- FR-16：展开/收起使用 150ms 高度与透明度过渡，标签输入使用既有 140/180ms 动画规范；书签网络请求和渲染不得阻塞 GPUI 主线程。

- FR-17：书签标签栏必须与待办标签栏共用 40px 行高、2px 行距、13px muted/ink 标签文字、11.5px muted/faint 计数、9px 色点和 `theme.active` 选中背景；选中背景以 Markd 同源 360/32/0.6 弹簧在行间执行 180ms 滑动，具体标签悬停时显示 40px 命中区的 Lucide `x`，不得挤动文本或计数。

## 验收标准

- AC-1：点击“书签”左侧打开独立书签界面，点击右侧图标只控制侧栏列表。
- AC-2：粘贴 `example.com` 回车后立即出现书签，重启后仍存在；后台抓取成功后标题和预览会更新。
- AC-3：输入普通关键词只过滤，不创建记录；重复或非法 URL 显示中文错误。
- AC-4：新建两个中文标签，可按标签筛选、多选分配、单独取消以及删除标签，计数实时准确。
- AC-5：双击标题可原位修改；复制后剪贴板等于 URL；删除后条目和持久化记录均消失。
- AC-6：导出的 Markdown 包含所有书签标题、规范化 URL 和 `#标签`。
- AC-7：元数据站点超时、返回错误状态或缺少 Open Graph 字段时应用不崩溃，书签仍可打开。
- AC-8：浅色和深色主题下，标签、文字、预览边框和 hover 操作均遵循现有 Synapse token。
