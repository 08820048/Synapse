# P2 writ 编辑内核适配规格

## 目标

保留 Synapse 的 GPUI 应用壳、页签、文件树和持久化边界，分阶段用 `writ 0.18.1` 的无头编辑能力替换项目内手写的 Markdown 编辑规则。当前已完成结构化 Enter、标准光标闪烁、基础选区/剪贴板和 tree-sitter-md 呈现适配，不接入 writ 的 winit/Vello 桌面层。

## 集成边界

- 固定依赖 `writ = 0.18.1`，关闭默认 `app` feature，禁止引入第二个窗口事件循环。
- 使用公开的 `writ::editor::EditorState`、`writ::buffer::RenderSnapshot`、Ropey 缓冲区和 tree-sitter-md 结构/行内样式结果。
- Synapse 的 `NoteDocument` 继续是保存到 Vault 的权威文档；writ 先作为单条编辑命令的结构分析器，验证通过后再规划长期缓冲区迁移。
- GPUI 继续负责输入法、字形绘制、点击命中和窗口焦点。

## 功能要求

- FR-1：普通 Enter 在非空无序列表项后自动续写相同列表标记。
- FR-2：普通 Enter 在非空有序列表项后自动写入递增序号，并保留 `.` / `)` 风格。
- FR-3：普通 Enter 在任务列表项后创建未勾选任务项。
- FR-4：普通 Enter 在列表之外仍插入普通换行。
- FR-5：空列表项按 Enter 时移除当前列表/任务标记并退出列表，不额外制造新的空列表项。
- FR-6：列表命令必须保持 Unicode 源码和字符光标正确，并继续触发现有脏状态与标题联动。
- FR-7：编辑器获得焦点并存在活动文档时，光标以约 530ms 周期显隐；输入、点击或方向移动后立即恢复可见并重新开始周期。
- FR-8：失去编辑器焦点时不绘制光标，后台闪烁任务不得阻止窗口或实体释放。
- FR-9：writ 的重叠样式运行必须转换为 GPUI 要求的完整、连续、互不重叠的 `TextRun`，保证链接、强调、代码和删除线可组合显示。
- FR-10：writ 的 UTF-8 buffer/display `SegmentMap` 必须转换成 Synapse 使用的 Unicode 字符映射，隐藏标记后仍可点击和选择源码。
- FR-11：writ 生成的单个显示行交给 GPUI `shape_text` 按父容器可用宽度软换行；wrapped layout 是绘制、鼠标命中、光标、选区和候选窗坐标的共同几何来源。

## 安全与性能要求

- SR-1：Synapse 与 writ 的边界显式转换 Unicode 字符索引和 UTF-8 字节索引，不得截断中文、emoji 或组合字符。
- SR-2：writ 生成的结果以最小公共前后缀差异写回 `NoteDocument`，不得在每次 Enter 时整篇替换 Rope。
- SR-3：不得启用 writ 默认 `app`、GitHub、网络、Git 或文件监听功能。
- SR-4：本阶段不启动应用、不运行截图或自动 UI 操作；通过状态、命令、格式化、Clippy、测试和构建验证。

## 验收标准

- AC-1：`- 第一项|` → `- 第一项\n- |`。
- AC-2：`9. 第一项|` → `9. 第一项\n10. |`，`9) 第一项|` 保持括号风格。
- AC-3：`- [x] 完成|` → `- [x] 完成\n- [ ] |`。
- AC-4：`- |` → `|`；普通段落只插入换行。
- AC-5：中文和 emoji 前后的光标转换测试通过。
- AC-6：光标闪烁状态可启动、切换、交互重置并通过纯状态测试。
- AC-7：进度文档明确标记本阶段只是 writ 分阶段适配，不得宣称完整替换已经完成。
